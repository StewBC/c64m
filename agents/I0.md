### 2. Config surface (master enable)

| Surface | Behavior |
|---------|----------|
| INI | `[debug] inspector=0\|1` |
| CLI | `--inspector` / `--no-inspector` |
| Default | **off** (play path stays cheap) |
| Budget INI | `[debug] inspector_memory_mb` default **128** |
| Budget CLI | `--inspector-memory=<MiB>` |
| Budget range | **0 or 16..4096**, same as `history_memory_mb` |

Help text must say the flag enables Inspector **recording** (checkpoints; default off),
not "start already Inspecting."

Keep existing `history_memory_mb` / `frame_ring_memory_mb` / `vic_ring_memory_mb`.
Do not retarget them.

**Semantics — pinned:**

1. `inspector=1` **implies** the checkpoint ring (from I1) and **arms the frame ring**
   (film). It does **not** arm HST1. HST1 already has `--history-memory` / `history-record`.
2. `inspector=0` forces the Inspector product path off. It does **not** stop standalone
   `history-record` / `frame-ring-record` / `vic-ring-record`.
3. Turning Inspector on from off is what arms the film ring. An agent that then calls
   `frame-ring-record off` gets what it asked for: Inspect still enters if checkpoints
   exist (A7); preview is pink. **No hidden re-arming.**
4. UI Inspect (I3) **requires** `inspector=1` (and, from I1, at least one checkpoint).
5. `inspector=1` with `inspector_memory_mb=0` is an **honest empty tape**, not a refuse
   and not a silent override of the typed 0. Warn once at startup. Garbage / out-of-range
   values follow existing `app_options` numeric handling (INI warns and uses 128; CLI
   rejects).

Typed **0 is honoured.**

### 3. Runtime plumbing (minimal)

- Plumb the bool + budget into `app_options` -> `runtime_config` -> runtime create.
- Module: `src/runtime/runtime_inspector.c` / `.h`. Names:
  `runtime_inspector_set_enabled` / `runtime_inspector_enabled` /
  `runtime_inspector_memory_mb`.
- Client: `runtime_client_inspector_set_enabled(client, enabled, token)` for tests
  and later I3 Record checkbox. **Not** a C64M verb in this phase.
- Command: `RUNTIME_COMMAND_INSPECTOR_SET_ENABLED` (internal).

**Arming (the function I1 extends):**

`runtime_inspector_set_enabled(rt, bool)` is the single off->on edge:

1. Sets `rt->inspector_enabled`.
2. If transitioning **off->on**: `runtime_frame_ring_set_recording(true)` if
   `frame_ring_memory_mb > 0`. Do **not** call `runtime_history_resume`.
3. If already on, or turning off: **do not** touch recorders.
4. Turning Inspector off does **not** stop standalone recording.

Call sites: worker startup (`rt->config.inspector`) ; `RUNTIME_COMMAND_INSPECTOR_SET_ENABLED`.

I1 adds one line here: start the checkpoint recorder. I4 will refuse to arm while
already in max/warp with the wipe policy on.

### 4. Discovery that contradicts a naive reading

HST1 and the frame ring **already record at startup** when their budgets are non-zero.
Default play already allocates 256+128 MB and records, Inspector or not. I0 does
**not** change that: `inspector=0` skips the Inspector arm, it does not stop HST1.

So `inspector=1` at a default-budget boot is a no-op on the **frame ring** itself
(already on). The I0 behaviour that is new:

- the enable flag exists and is readable
- off->on after a standalone `frame-ring-record off` **re-arms film**
- while Inspector stays on, that standalone off is **not** undone
- HST1 is never touched by this switch
- `inspector=1` + typed 0 budget is empty tape + one stderr warning

I0 does not allocate the checkpoint 128 MB; `inspector_memory_mb` is stored on the
runtime for I1. Play-cheap for Inspector is "no checkpoint work + default off."

Document the aggregate honestly: if the user also leaves default HST1+film on,
resident debug memory is 256 + 128 + 128 = 512 MB. That is two products plus film,
not one master switch.
