# I4 — Max and warp wipe Record

**Status:** Landed.  
**Epic:** [`inspector.md`](inspector.md)  
**Prev / Next:** [`I3.md`](I3.md) / —  
**Depends on:** I1 recorder; I3 Inspector tab (lock the checkbox). I2 enter/leave if Inspect is active.

Related: D17 · [`inspector.md`](inspector.md) · turbo modes in `src/runtime/runtime.h`.

---

## Goal

Entering **max** (turbo 2) or **warp** (turbo 3) must not leave a frozen checkpoint
under a live cycle that keeps running. That makes Inspector Duration grow without
cap and a scrubber release land on the last pre-max checkpoint (slider slammed
left).

**Product shape:** wipe Record on enter max/warp; restore Record on leave into an
**empty** window.

Turbo 1 (normal) still records.

---

## Shape (pinned)

New policy flag, default **true**:

| Surface | Name |
|---------|------|
| INI | `[debug] inspector_off_on_max=true\|false` |
| CLI | `--inspector-off-on-max` / `--no-inspector-off-on-max` |

c64m has no `history_off_on_max`. Do **not** pause HST1 from this flag. HST1 is
the other product.

Applies to turbo **2 and 3** only.

1. **Enter max or warp** — remember whether Record was on.
2. If Inspect is active, **leave Inspect** (restore NOW) first, then wipe.
3. **Wipe** the Inspector tape (checkpoints + input log; film ring if Record was
   on) and **turn Record off**. Inspector looks like Record is off: no Duration,
   no Inspect, no scrubber. Record checkbox is **locked**. No help dump on the tab.
4. **Leave max/warp** (return to turbo 1) — restore the remembered Record state.
5. **If Record was on**, start recording again into an **empty** window from that
   moment.

If Record was already off, it stays off across the round-trip.
`--no-inspector-off-on-max` is the opt-out (keep recording in max/warp).

A Record click **while in max/warp** does not start a tape. Enable is remembered
for leave-max; disable clears that memory. The checkbox stays locked off in the UI.

`runtime_inspector_set_enabled` while already in max/warp with policy on does
**not** arm the recorder (I0 arming gain).

---

## Why

Duration is `(live - oldest snapshot) / clock_hz`. Live is current
`machine.clock.cycle`. With the recorder stopped but old snapshots kept, live ran
away and Duration was unrecorded max-run time. Preview used the frame ring (warp
does not even record film); land used the last checkpoint (frozen). Those clocks
disagreed.

Wiping on **enter** matches the advertised discard (one Opt+T throws the tape
away) instead of discarding only on leave.

Warp already skips live pixels (`control-port.md`). Inspector must not pretend a
pre-warp tape is still a valid timeline under a running cycle counter.

## Non-goals

- Turbo 1 discarding history
- Pausing HST1
- Dual windows / islands (D17 still one interval)

## Landed

2026-08-23. Enter max (turbo 2) or warp (turbo 3) remembers Record, leaves
Inspect first if active (NOW restored), wipes the Inspector tape (checkpoints,
input log, and film if Record was on), and turns Record off. Leave to turbo 1
restores remembered Record into an empty window at the new live cycle.
Record-off stays off. HST1 is not paused or wiped.

- Policy: `[debug] inspector_off_on_max` (default true); CLI
  `--inspector-off-on-max` / `--no-inspector-off-on-max`.
- Runtime: `inspector_enabled_saved_for_max`; `runtime_inspector_apply_max_policy`
  on turbo commit. Max <-> warp stays in the wipe regime.
- `runtime_inspector_set_enabled` while already in max/warp with policy on does
  not arm the recorder; enable is remembered for leave, disable clears it.
- Inspector tab: Record checkbox locked off while in max/warp with policy on;
  a click does not arm a tape. No banner dump.
- Gate: `runtime_inspector_replay` pins wipe-in-max, restore-on-leave,
  Record-off stays off, warp, opt-out, inspect+max NOW restore. `app_options`
  pins the flag. 77/77 ctest green.
